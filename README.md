# Local Mail

A small local-first Gmail inbox. Email is cached in SQLite, classified by a local Hugging Face zero-shot model, and drafts are generated by a separate local Qwen GGUF through `llama-server`. No hosted AI provider is configured or used.

## Setup

1. Copy `.env.example` to `.env.local` and set `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` from a Google OAuth client configured for the exact redirect URI in `GOOGLE_REDIRECT_URI` (default: `http://localhost:40000/api/gmail/callback`). This app-specific overlay preserves any existing `.env`. No Gmail password is requested or stored.
2. Set `CLASSIFIER_MODEL_PATH` and `LLAMA_CPP_MODEL_PATH` to the local model paths. The classifier path can use the existing snapshot shown in `.env.example`. Install `llama.cpp` separately if `LLAMA_SERVER_PATH` is not already available.
3. Run `python -m venv .venv && .venv/bin/pip install -r requirements.txt` (or install into the supplied venv), then `cd frontend && npm install`.
4. Run `make dev`. `make check-dev-ports` checks both ports before either server starts.

Press Ctrl+C to stop both dev servers and their child processes; backend shutdown also stops the persistent `llama-server`. `make dev` checks ports 40000, 40001, and 40002 first (override with `BACKEND_PORT`, `FRONTEND_PORT`, and `LLAMA_PORT`). If a server from an earlier run is still holding a port, inspect it with `ss -ltnp` and stop that specific PID before restarting. Reply generation disables Qwen's reasoning mode by default (`LLAMA_REASONING=off`) so its token budget is used for the actual reply.

Use `make stop` (or `bash scripts/stop-dev.sh`) to stop tagged processes launched by this project, including the backend, frontend, and its `llama-server`. This only recognizes processes started through the updated Makefile/dev launcher; it does not kill unrelated processes that happen to use the same ports.

To run each service in its own terminal, start `llama-server` using the configured model/port, then run the backend and frontend commands. The backend reuses a healthy `llama-server` at `LLAMA_SERVER_URL` instead of starting a duplicate.

The DeBERTa model weights are loaded on the first classification. Startup status checks its files and local runtime, and loads only the small tokenizer to confirm it works. `CLASSIFIER_MODEL_PATH` is preferred; to select a cached model by ID instead, leave that setting blank and set `CLASSIFIER_MODEL_ID`. Hugging Face runs offline and only resolves IDs already in its local cache. Qwen is loaded once by a persistent `llama-server` process, started lazily for the first draft. Missing model files and startup/inference errors are surfaced in the UI. No model weights are downloaded automatically.

## Request flow

Vue calls FastAPI endpoints. Gmail OAuth credentials and message metadata/body are stored locally in SQLite. Sync fetches messages from Gmail before opening a short transaction; classification runs locally, then the fetched data is inserted in a short transaction. A reclassification request targets one email. Draft generation loads the email, releases all DB resources, calls the local llama-server, then saves the result in a new short transaction. Sending requires a separate confirmation in the composer and a distinct API action. Deleting local messages and drafts preserves the OAuth connection.

SQLite uses WAL and a 5 second busy timeout to reduce reader/writer contention. WAL can leave `-wal`/`-shm` files while the app is active; they are normal SQLite files. No transaction is held during Gmail network requests or model inference.

## API

`GET /api/status`, `GET /api/emails`, `GET /api/emails/{id}`, `POST /api/sync`, `POST /api/emails/{id}/reclassify`, draft generate/save/approve/delete endpoints, `POST /api/emails/{id}/send`, OAuth start/callback, and `DELETE /api/local-data`.

The send action is never triggered by draft generation or approval. Local deletion removes cached email data and drafts only; it does not call Gmail.
